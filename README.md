# Verdict Proxy Service (`3proxy` HTTP/HTTPS) 🐳

Готовий та легкий (~5 МБ) Docker-пакет прозорого **HTTP / HTTPS (`CONNECT`) проксі-сервера** без авторизації за логіном/паролем на базі офіційного образу [`docker.io/3proxy/3proxy:latest`](https://hub.docker.com/r/3proxy/3proxy).

Доступ відкрито **виключно за білим списком IP-адрес** (`auth iponly` у `3proxy`), який зручно налаштовується через `.env` (за замовчуванням — лише `185.112.41.130`). Будь-які підключення з інших IP автоматично відхиляються, а при порожньому `ALLOWED_IPS` контейнер захищено від випадкового запуску відкритого проксі.

---

## 🚀 Швидкий запуск на прод-сервері (за 1 хвилину)

Підключіться по SSH до вашого Linux-сервера (на Ubuntu 24.04 за потреби встановіть плагін Compose v2: `apt update && apt install -y docker.io docker-compose-v2`) і виконайте:

```bash
git clone https://github.com/ivan0k/verdict-proxy-service.git
cd verdict-proxy-service
cp .env.example .env
nano .env
```

За замовчуванням у `.env` вже виставлено доступ лише для `185.112.41.130` та зовнішній порт `8888`:

```env
ALLOWED_IPS=185.112.41.130
PROXY_PORT=8888
```

Запустіть сервіс у фоні:

```bash
docker compose up -d --build
```

Перевірити статус та логи підключень:

```bash
docker compose ps
docker compose logs -f
```

## 🔐 Керування списком дозволених IP (`.env`)

У змінній `ALLOWED_IPS` можна вказати одну або декілька IP-адрес чи підмереж CIDR через кому:

```env
# Один IP:
ALLOWED_IPS=185.112.41.130

# Кілька IP або підмереж через кому:
ALLOWED_IPS=185.112.41.130,203.0.113.25,198.51.100.0/24
```

Після зміни `.env` застосуйте нові правила однією командою:

```bash
docker compose up -d
```

## 🧪 Перевірка роботи проксі

Виконайте з машини з дозволеним IP (`185.112.41.130`):

```bash
# Перевірка HTTPS через проксі (поверне зовнішній IP вашого проксі-сервера)
curl -x http://<IP_ПРОКСІ_СЕРВЕРА>:8888 "https://api.ipify.org?format=json"

# Перевірка звичайного HTTP через проксі
curl -x http://<IP_ПРОКСІ_СЕРВЕРА>:8888 http://httpbin.org/ip
```

При спробі запиту з будь-якої іншої IP-адреси `3proxy` миттєво закриє/відхилить запит за правилом `deny *`.

## ⚙️ Змінні середовища (`.env`)

| Змінна | За замовчуванням | Опис |
|---|---|---|
| `ALLOWED_IPS` | `185.112.41.130` | Білий список клієнтських IP або CIDR через кому (`185.112.41.130,1.2.3.4,10.0.0.0/24`) |
| `PROXY_PORT` | `8888` | Зовнішній TCP-порт, на якому слухає HTTP/HTTPS проксі |
| `PROXY_BIND_IP` | `0.0.0.0` | Локальний інтерфейс прослуховування |
| `OUTGOING_IP` | *(порожньо)* | Конкретний вихідний IP сервера (якщо на хості декілька IP-адрес) |
| `ANONYMOUS_MODE` | `false` | `false` — звичайний прозорий проксі; `true` — приховувати заголовки проксі (`-a`) |
| `ALLOWED_TARGET_PORTS` | *(порожньо = всі)* | Обмеження цільових портів через кому, напр. `80,443,8080,8443` |
| `BLOCK_LOCALHOST` | `true` | Захист від SSRF-звернень через проксі до `127.0.0.0/8` та `169.254.169.254` хоста |
| `MAX_CONN` | `2000` | Максимальна кількість одночасних з'єднань |
| `DNS_SERVERS` | `1.1.1.1,8.8.8.8` | DNS-резолвери для вбудованого кешу `3proxy` (`nscache 65536`) |
| `ENABLE_LOGS` | `true` | Вивід логів доступу у `stdout` (`docker compose logs -f`) |

## 💡 Важлива примітка щодо мережі (`network_mode: host`)

У `docker-compose.yml` увімкнено `network_mode: host`. Це зроблено спеціально для проксі з фільтрацією по IP на Linux-серверах:
- `3proxy` слухає напряму на зовнішньому порту хоста (`PROXY_PORT=8888`) і гарантовано бачить **реальний зовнішній IP клієнта** (`185.112.41.130`), а не внутрішній шлюз Docker bridge (`172.18.0.1`) після NAT;
- відсутні зайві витрати `conntrack` Docker-моста при великій кількості з'єднань.

Переконайтесь, що порт `8888/tcp` відкритий у вашому фаєрволі (наприклад, `ufw allow from 185.112.41.130 to any port 8888 proto tcp` або у Hetzner Cloud Firewall).
